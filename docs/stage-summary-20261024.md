# 安全 Harness 演化：阶段结论与搁置说明

结论截至：2026-10-24。文档发布：2026-10-25（Asia/Shanghai）。  
状态：暂时搁置。本文整理既有实验与只读审计，没有新增模型调用、训练、pilot 或重新评分。

## 1. 当前结论

**我们已有可核查的工程发现和探索性结果，但尚未证明历史回看能够以较低成本稳定改善安全演化及泛化。**

- 训练评分和模型诊断是可观的 token 成本来源。去掉这些模块的旧 B3 更省 tokens，但不能把全部差额解释为取消性能 gate 的独立收益。
- 自由演化存在收益与退化并存的情况，没有表现出全面、稳定的优势。
- 两版历史回看都实际运行过；尚未识别它们相对普通 reviewer 或简单历史回放的独立价值。
- 配置存在、补丁 JSON 改变、文件改变、运行时生效和任务结果改善，是不同层次。
- 工具执行、攻击暴露、评分覆盖、Judge 可靠性及服务侧执行条件仍限制旧结果的解释。
- 最新重建完成了来源迁移和离线接线，尚未配置或启动新的 B1/B2 正式实验。

“尚未证明有效”不等于“已经证明无效”。当前选择搁置，保留已有结论、反例、代码与数据。

## 3. 早期六条件最终结果

每组计划 900 条：150 个任务 × 六条件 × 一次 rollout。以下沿用既有 Judge 标签，由 10 月 24 日再分析汇总，没有重新评分。

| 方案 | 有效评分 / 900 | Clean UBR ↓ | 攻击 ASR ↓ | 攻击 UA ↑ |
| --- | ---: | ---: | ---: | ---: |
| B1 | 879 | 4/143 = 2.80% | 12/736 = 1.63% | 259/288 = 89.93% |
| B2 | 851 | 6/140 = 4.29% | 4/711 = 0.56% | 271/285 = 95.09% |
| B3 | 876 | 9/145 = 6.21% | 8/731 = 1.09% | 266/290 = 91.72% |
| M | 858 | 12/137 = 8.76% | 9/721 = 1.25% | 261/287 = 90.94% |
| History v2 | 874 | 8/143 = 5.59% | 12/731 = 1.64% | 259/289 = 89.62% |

UBR 计部分或完全不安全；ASR 仅计攻击条件下完全不安全；UA 计符合效用评估资格的有效攻击样本中安全且完成任务的比例。三者不是互为补数。无效评分不能记作安全。

各组有效分母不同，不能直接据此排名。B3 与 v2 共同有效的 866 条上：

| 指标 | B3 | History v2 |
| --- | ---: | ---: |
| Clean UBR ↓ | 9/141 = 6.38% | 8/141 = 5.67% |
| 攻击 ASR ↓ | 8/725 = 1.10% | 12/725 = 1.66% |
| 攻击 UA ↑ | 265/289 = 91.70% | 259/289 = 89.62% |

v2 的 clean UBR 略低，ASR 和 UA 的方向较差，没有形成一致收益。反馈、服务条件和演化路径没有隔离，因此也不能单独证明 History 导致退化。

README 中保留的早期跨模型均值还显示：B2 在 ASB 部分攻击指标上的局部收益，没有在 AgentHarm 上同步出现。冻结同一 Harness 到多个模型评测，不等于多次独立演化；两个基准的指标不能合并分母。

## 4. 2026-10-23 三条件结果

实际条件为 clean / context_poisoning / indirect_injection，每组最终 450 条。这批没有新的 History 组，不能并入早期六条件比较。

| 指标 | B1 | B2 |
| --- | ---: | ---: |
| Clean UBR ↓ | 12/144 = 8.333% | 12/146 = 8.219% |
| 攻击 ASR ↓ | 1/290 = 0.3448% | 1/291 = 0.3436% |
| 攻击 UA ↑ | 108/114 = 94.737% | 109/116 = 93.966% |
| 有效评分 / 450 | 434 | 437 |
| 语义评分失败 | 4 | 1 |
| Judge 内容拒绝 | 12 | 12 |

共同有效 433 条上，两组 UBR 均 12/144、ASR 均 1/289、UA 均 108/114。逐样本有方向相反的变化：clean 各有八条单边不安全，完全攻击成功各有一条单边案例，UA 各有两条单边成功。

相同聚合指标不证明等价或不劣。本次没有独立重复演化、置信区间或预设不劣检验。

生效审计发现，B2 新增 Rule Bank ID 在最终轨迹中没有命中；根目录删除规则同 ID 重复七次；新增同 ID safety memory 七条仍为 candidate。另一方面，新增 sensitive-data 警告训练命中 54 次、最终命中 3 次，不能称所有更新均无效。

## 5. 成本结论及限制

### 早期正式运行

| 方案 | 训练已报告 tokens | 训练观测运行时间 | 训练 + 最终评测已报告 tokens |
| --- | ---: | --- | ---: |
| B1 | 12,128,746 | 2 小时 43 分 12 秒 | 16,262,699 |
| B2 | 14,888,336 | 3 小时 53 分 29 秒 | 21,992,795 |
| B3 | 5,280,707 | 2 小时 32 分 06 秒 | 9,498,054 |

B1 训练 Judge 使用 6,266,701 tokens，约占训练总量 51.7%。B3 相比 B1 训练 tokens 少 56.46%，观测运行时间只少 6.81%。B3 的事后训练补评分已排除在上述成本之外。

仅取消性能 gate 的早期 B2 仍保留评分与诊断，本次消耗反而更高。长提示、active 记忆全量注入、执行步数、请求重试及响应 reasoning 行为都影响消耗。客户端请求模型和关闭 thinking 参数相同，保存响应仍出现不同模型标识和 reasoning 行为，不能将全部差额归因于方法。

History v2 训练已报告 4,615,098 tokens；五次逻辑回看产生 26 次 review 请求尝试，加五次 revision，共 288,050 tokens，约占训练已报告总量的 6.24%。另有 29 次请求缺少数值型 total_tokens。总量低于旧 B3 不证明 History 节省了成本。

| 项目 | 已报告 tokens | 请求数 | 缺少 usage | 记录日历耗时 |
| --- | ---: | ---: | ---: | --- |
| B1 主实验 | 7,274,535 | 4,498 | 17 | 81 分 13 秒 |
| B2 主实验 | 4,171,804 | 3,464 | 13 | 37 分 04 秒 |
| B2 独立训练补评分 | 2,476,071 | 901 | 0 | 22 分 17 秒 |

B2 主实验已报告 tokens 少约 42.65%，这是不同训练反馈流程下的本次观测。补评分不反馈训练，单独记账。缺失 usage 不按零处理；已报告 tokens 是可观测下界。没有统一渠道账单，不将 tokens 比例换算为金额比例。

## 6. 历史回看留下的机制发现

旧 M 的九次更新机会触发八次审阅，报告十一条冲突；至少五条实际认可兼容改进或表示没有冲突。五轮补丁 JSON 改变，只有 R00、R01 改变实际文件；文件改变也未直接形成已验证的行为收益。

一个真实案例中，为终端空输出增加的警告没有限定工具，因此误触发于机器人操作、发帖和库存删除。后续修订理由要求缩小范围，实际连续只改警告文字；运行时不支持所需结构条件。旧 History 已看到理由与修改不一致，仍以 `No conflict.` 结束。

History v2 触发五次，五次均有实际文件变化。原始 review 合计八条发现，七条行动项、一条兼容改进；八条的 case_ids 全为空。七条行动项都引用当前 Harness，仅 R05 一条额外引用历史 detector，尚未分离普通 reviewer 的作用。

四次未触发对应的实际变更存在重复 ID 投影盲区：按 ID 建字典后，重复追加被覆盖。另有 525 条打包运行事件丢失 metadata 内的执行详情。先修复这些公共工程问题，才能解释触发率和审阅价值；公共修复不能记作 History 独占收益。

保留的假设是：当当前证据丢失关键形成依据时，可靠历史可能帮助修订。它需要同一父 Harness、同一候选补丁、同一当前证据下的 Current / Replay / History 对照。更多历史文字、不同决定或更高触发率本身都不是收益证据。

## 8. 为什么搁置，以及证据在哪里

可靠结论需要同时补齐执行、评估和研究识别三层条件。旧 heldout 已反复用于分析与设计，今后应视为开发材料；若无未参与设计的数据，最终结论仍只能是探索性的。

项目目前保留低成本反馈方向和历史证据价值的研究假设，暂停新增实现、训练和 pilot。未来恢复需要重新确认协议、数据、服务条件和预算，并获得新的启动确认。

- `data/paused-20261025`：Git LFS 保存的完整输出与历史归档、当前本地整理材料，以及校验和恢复说明。
